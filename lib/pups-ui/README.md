# pups-ui

The pages of the **Personal Upload Server** ([RFC-6](https://github.com/bigwide-net/RFCs/blob/main/RFC-6-Personal-Upload-Server.md)) that the owner sees, and the homepage of the owner's domain: one set of HTML, styles and texts for all implementations, so that they look and behave the same.

## What it does

- **Owner pages**: the consent screen apps send the owner to, setup, login, the apps page (with the mentions in the inbox), the feeds page (WebSub), the comments page (the comments in the inbox, and auto-moderation), the password page, the start page `/pups/` and the page *Homepage*.
- **The homepage**: [webpup](../../webpup), built and bundled as a module, served at `/` and `/p/…` while the owner has installed it, with its themes and `webpup-config.json`.
- **Inbox pages**: the page that dismisses an inbox item, for readers without RFC-9 actions (used by [pups-inbox](../pups-inbox)).
- **Shared rules**: the sanitizer for untrusted text (client metadata, scopes, paths, host-meta.json), `isPrivate()` and the wording of scopes, and `texts.json`.

The functions are pure: a server passes in plain data (its settings, the parsed scopes, the grants) and gets HTML or a `Response`. Request handling, storage and authentication stay in the servers.

## Contents

- `src/html.ts`: the page frame with its security headers, messages, and `confirmFields()`: how a form is confirmed. With a passkey, nothing visible (`owner.js` asks for it; the servers don't accept the password then); without one, `owner.js` asks for the password in a dialog, and only pages without script (`noscript`) or the login page have a password field.
- `src/scopes.ts`: `isPrivate()`, the consent groups of the scopes and their wording.
- `src/identity-tokens.ts`: identity tokens (RFC-10): the scope, the checks of a token exchange request, the signing key, the JWK Set and the signed token, with Web Crypto only; each server keeps the key and the log.
- `src/consent.ts`: the consent screen.
- `src/owner.ts`: setup, login, the apps page, the feeds page and the password page.
- `src/inbox.ts`: the inbox and auto-moderation sections of the apps and comments pages, and the pages that dismiss, publish or reject an inbox item.
- `src/homepage.ts`: the start page `/pups/`, the page that installs webpup, and webpup's files at `/`, `/p/…` and `/webpup-config.json`.
- `src/webpup-files.ts`: the build of webpup, generated by `npm run sync-webpup` (which builds webpup first; `--no-build` uses its current `dist/`). A test fails while it differs from `webpup/dist`.
- `src/sanitize.ts`: the sanitizer for untrusted text.
- `texts.json`, `src/texts.ts`: the texts of the consent screen, the permission lists and the confirmation fieldset, read with `t(key, vars)`.
- `public/pups/assets/`: `owner.css` and `owner.js`, served at `/pups/assets/`. `public/_headers` sets their headers on Cloudflare.

## Page session

In same-domain mode, RFC-6 allows a session only in the memory of the open owner page. `owner.js` holds it:

- Forms with `data-session` (the management pages) are sent with `fetch` and the header `PUPS-Session`: the session, or `new`. The answer replaces the page (`history.pushState` for the links of the owner navigation).
- After a successful confirmation, or with a valid session, the server answers with a renewed session in the same header. Without one in the answer, `owner.js` forgets its session.
- Submit buttons with `data-view` (Reload) only show the page again. With a session they submit without asking for the passkey, and the server shows the page without a confirmation. Every other submit still asks.
- The servers issue and check the token (signed, 15 minutes idle, 1 hour at most, tied to the owner's password and passkeys). In auth subdomain mode the cookie is the session, and no token is issued.

Pages with the owner navigation are sent with `Cross-Origin-Opener-Policy: same-origin`, and every page with `connect-src 'self'`.

## Use

The servers in this repository depend on it as a local package:

```json
"dependencies": { "pups-ui": "file:../lib/pups-ui" }
```

It ships TypeScript sources; the servers' bundlers (wrangler, esbuild) or ts-node and ts-jest (pups-server) compile them. The servers need `"resolveJsonModule": true` for `texts.json`.

- `import { consentPage, appsPage, … } from 'pups-ui'`
- Cloudflare serves the assets as static assets: `"assets": { "directory": "./node_modules/pups-ui/public" }` in `wrangler.jsonc`.
- Servers that serve them from code import them as text: `import { ownerCss, ownerJs } from 'pups-ui/assets'` (needs `?raw` imports, see `src/raw.d.ts`).

All styling goes into `owner.css`: the pages are plain semantic HTML without classes or inline styles. A comment at the top of the file describes their structure.

## Development

```
npm install
npm test
npm run typecheck
```

After a change, run the tests of all servers too, and `scripts/sync-ui.sh` in pups-php if you changed `texts.json` or the assets. After a change to webpup, run `npm run sync-webpup` here (and pups-php's `scripts/sync-webpup.sh`).
